# Vueling flights

Use the `vueling` CLI for live prices, flight itineraries, bundle prices, and flight status: `flights`, `select`, `extras`, `trips`, `schedule`, `calendar --prices`, `deals`, `routes`, `fees`, `alerts`, and `status` call the JSON APIs behind Vueling's website over HTTPS without opening a browser or reading cookies. Use the other commands to resolve airports and build official calendar and flight-selection links. Fall back to `--browser` (rendered pages in the user's Chrome) only if the API path fails.

## Boundaries

- Read-only: search and inspect offers only. Never book, pay, check in, or change a reservation. The single exception is `vueling extras`: to reveal a flight's exact seat/bag/extra prices it puts the fare in the cart of its own fresh anonymous session (no passengers, no payment, no commit) and always ends that session. Run it once per flight, only when the user asks what a seat, bag or extra costs on a specific flight, and never loop it.
- By default the CLI sends HTTPS requests that mimic Chrome (TLS fingerprint and headers) to Vueling's undocumented APIs, using the anonymous session any visitor gets. Never add account credentials or cookies to these requests. If they fail (e.g. `HTTP 403` from the CDN), retry once with `--browser`. With `--browser` on macOS the CLI uses Chrome Apple Events, which needs **View > Developer > Allow JavaScript from Apple Events**; that permits AppleScript callers to run JavaScript in pages, so never enable it without the user's explicit approval. On other systems `--browser` attaches to a local Chrome DevTools endpoint (`http://127.0.0.1:9222` by default; `--cdp-url` selects another loopback endpoint). DevTools grants browser control, so never expose it on a network.
- Do not copy the user's session tokens or cookies into the CLI, files, or output. The CLI keeps its own anonymous session in the user cache directory (`vuelingcli/session.json`, mode 0600); never print or share that file. If `flights` or `select` fail with a session/authentication error, run `vueling session clear` and retry once; `vueling session refresh` keeps it alive while the user compares options.
- When reading through browser UI, use its accessibility tree or rendered page text and leave fare buttons untouched. The route, times, flight number, and displayed price are visible in the offer card.
- Use `vueling calendar ORIGIN DESTINATION --date DATE --return RETURN_DATE --prices --json` to read outbound and return fares from Vueling's fare calendar (about 11 months ahead; return dates must be within 330 days of departure). Add `--month` to list every visible day fare of each month with the cheapest day (`days`/`cheapest`, `returnDays`/`returnCheapest`). Treat these as calendar fares, not a final booking quote.
- When the user has an origin but no fixed destination ("¿a dónde puedo ir barato desde X?"), use `vueling deals ORIGIN --json` (add `--from`, `--months`, `--max`, `--direct`, `--to`) to list the cheapest fare per destination, then read that day with `flights`.
- To answer "where does Vueling fly from X?" (or "is there a direct flight to Y?"), use `vueling routes ORIGIN --json` (`--direct`, `--country`); it also says whether resident and large-family discounts apply.
- For "how much is a checked bag / seat / pet / date change?" in general, run `vueling fees maleta --json` (or `asiento`, `mascota`, `cambio`) and quote the online range, saying it varies by route and date. For a specific flight, run `vueling extras ORIGIN DEST --date D --flight VYnnnn --json` and quote the exact prices.
- With flexible dates and a stay length ("cheapest long weekend", "4–5 nights in March"), run `vueling trips ORIGIN DEST --from D --to D --nights 3-5 --json`, then confirm the chosen pair with `select --cheapest --return R --return-cheapest`.
- For "which days does Vueling fly X–Y?" or seasonal routes, run `vueling schedule ORIGIN DEST --months 6 --json` (`--days` adds flight number, time and fare per day). If it shows no flights, check `routes ORIGIN` to see whether Vueling serves the route at all.
- When the user wants to be told when a fare drops, run `vueling calendar ORIGIN DEST --date D [--return R] --prices --watch 60 --below PRICE` (in the background when possible): one route at a time, never more often than every 30 minutes (the CLI enforces it); it exits once the fare is at or under the threshold.
- When a flight is delayed or cancelled, or the user asks about strikes or disruptions, run `vueling alerts --json` and quote Vueling's notice and link if one is active.
- Use `vueling flights ...` or Vueling's visible search form to read flight times and numbers. When the user is a resident of the Balearic or Canary Islands, Ceuta or Melilla, or has a large-family title, add `--discount` (see the reference) instead of quoting the full fare. When the user wants bags, a seat or changes included, run `vueling select ORIGIN DEST --date DATE --flight VYnnnn` (or `--cheapest`; add `--return DATE --return-flight|--return-cheapest` for return trips) and quote the bundle totals (Fly Light, Fly, Fly Pro, Fly Grande) with the tax breakdown. `select` mirrors clicking a fare on the website but only reads prices; it never sells or books. Hand the user its printed link to confirm on vueling.com themselves. With infants, quote the total including the separate infant fee line. When a flight's arrival shows `+1` (JSON `arrivalDate`), tell the user it lands the next day.
- In the browser, stop before selecting a flight/fare or continuing into passenger details, seats, extras, or payment. Never book, pay, check in, or change a reservation.
- Chrome 136+ ignores `--remote-debugging-port` for the default Chrome data directory; do not work around this by copying the user's profile. Never enable remote debugging, relaunch Chrome, or change its startup flags without the user's explicit approval. See [Chrome's remote-debugging changes](https://developer.chrome.com/blog/remote-debugging-port).
- Stop if the site requires a CAPTCHA or login the user has not completed.
- Run live lookups one at a time and only as needed; never retry in a loop. `vueling status --watch` and `vueling calendar … --prices --watch` are the only polling allowed: watch at most one flight or route at a time and never lower their minimum intervals (5 minutes for status, 30 for prices). With `--browser`, if tickets.vueling.com stays on "Cargando..." or `flights` reports no rendered results, stop and ask the user to sign in to Vueling in that Chrome profile (a signed-in session has resolved this) or try a manual search, then retry once. `Vueling shows no flights for that route on the requested date` is a real answer, not a stall: offer other dates (`calendar --prices --month`) instead of asking the user to sign in.
- Ask for origin, destination, dates, and passenger counts when missing. Do not infer travel dates.
- Prefer `--json` for programmatic workflows and keep diagnostics on stderr.
- Do not request or store account passwords or payment details.

## Typical workflow

1. No fixed date: `calendar --prices --month`, `trips --nights N-M` for a stay length, `schedule` for which days it flies, or `deals ORIGIN` with no fixed destination.
2. That day's options: `flights ORIGIN DEST --date D [--return R] --json`, filtered with `--direct`, `--after`, `--cheapest`, `--limit`.
3. Real price with bags/seat/changes: `select ORIGIN DEST --date D --flight VYnnnn|--cheapest [--return R --return-flight VYnnnn|--return-cheapest] --json`; give bundle totals and the printed link. Exact seat or single-extra prices: `extras … --flight VYnnnn`.
4. Not ready to buy: `calendar … --prices --watch 60 --below PRICE`.
5. Before travel: `status VYnnnn` and `alerts`.

## Commands

For complete command syntax, option meanings, date formats, and output schemas, read [the CLI reference](references/cli-reference.md). Quick examples: `vueling flights BCN AGP --date +7 --return +14 --json`, `vueling flights BCN AGP --date +7 --direct --after 08:00 --cheapest --limit 3 --json`, `vueling flights BCN AGP --date +7 --return +14 --nearby --json` (adds the cheapest calendar day of each month as `nearby`/`returnNearby`), `vueling select BCN BIO --date +9 --flight VY1460 --json` (price breakdown and bundle totals, nothing booked), `vueling select BCN BIO --date +9 --cheapest --return +14 --return-cheapest --direct --json` (cheapest direct return trip with bags/seat bundles), `vueling session refresh` (keep the reused anonymous session alive), `vueling extras BCN BIO --date +9 --flight VY1460 --json` (exact seat/bag/extra prices), `vueling trips BCN BIO --from +7 --to +40 --nights 3-5 --json`, `vueling schedule BCN ESU --months 6 --json`, `vueling calendar BCN BIO --date +9 --prices --watch 60 --below 40`, `vueling calendar BCN AGP --date +7 --return +14 --prices --json`, `vueling calendar BCN LHR --date +7 --prices --month --currency GBP --json`, `vueling deals BCN --max 30 --direct --json`, `vueling deals Barcelona --to bilbao,sevilla --months 12 --json`, `vueling routes Bilbao --direct --country Italia --json`, `vueling calendar Barcelona "Palma de Mallorca" --date tomorrow --open`, `vueling search BCN AGP --date +7 --adults 2 --json`, `vueling status VY1158 --date today --json`, `vueling status BCN PMI --json`, `vueling status BCN PMI --date yesterday --json`, `vueling status VY1158 --watch 10 --json`, `vueling alerts --json`, `vueling fees maleta --json`, `vueling airports paris --toon`, and `vueling version --json`. Quote multi-word city names; ambiguous cities must be passed by IATA code. `flights`, `select`, `extras`, `trips`, `schedule`, `calendar --prices`, `deals`, `routes`, `alerts`, `fees`, and `status` read Vueling's JSON APIs; only `flights`, `calendar --prices`, and `status` accept `--browser` to read the rendered pages in Chrome instead; `status` also accepts past dates (if a flight number finds nothing, search its route — Vueling's number lookup misses some flights); `search`, `link`, and calendar without `--prices` only create URLs.
